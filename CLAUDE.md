# Cortex Studio

Editor de video de escritorio (Electron 44 + React 18 + Vite 5 + FFmpeg). Toda la interfaz, los comentarios, los mensajes de commit y la documentación están en **español**.

Repositorio: https://github.com/Nyra31/cortex-studio (rama `main`, etiqueta `v0.1.0` = primera versión con instalador).

Releases: cada versión publicada tiene etiqueta `vX.Y.Z` y una release en GitHub con `Cortex-Studio-Setup-X.Y.Z.exe`, **`Cortex-Studio-Setup-X.Y.Z.exe.blockmap` y `latest.yml`** adjuntos (los tres de `release/`; sin `latest.yml` las actualizaciones automáticas no ven la versión). Pasos: subir `version` en `package.json`, `npm run dist`, commit, etiqueta, push y crear la release (no borrador) subiendo los tres archivos (con `gh` si está instalado; si no, con la API de GitHub usando el token de `git credential fill`). El repositorio es **público** desde la v0.6.0 (licencia GPL-3.0, `LICENSE`).

## Comandos

```bash
npm start        # vite build + electron .
npm run dev      # Vite en 127.0.0.1:5173 + Electron con recarga
npm run dist     # instalador NSIS en release/Cortex-Studio-Setup-<versión>.exe
npm run icon     # regenera build/icon.png (scripts/make-icon.js)
```

No hay tests ni linter. Para comprobar un cambio: `npm run build` (debe compilar sin errores) y probar la app con `npm start`.
Pruebas automáticas (no están en el repo; se escriben en una carpeta temporal): un script de Electron que sustituye `dialog.showOpenDialog` para abrir un `.cortex` de prueba, hace `require('electron/main.js')` y maneja la app con `webContents.executeJavaScript` y `sendInputEvent`. Lanzar con `node_modules/electron/dist/electron.exe script.js` tras `vite build`, y pasar antes `node --check` al script (un error de sintaxis abre un diálogo de error en la pantalla del usuario). Para comparar la vista previa WebGL con el render, usar `capturePage(rect)` (leer el lienzo desde la página da negro). Si la captura sale con un fotograma viejo (la ventana no se está pintando), antes `win.focus()` + `webContents.invalidate()` y esperar un poco.
Si Electron se comporta como Node, la variable `ELECTRON_RUN_AS_NODE` está definida en la terminal (VS Code la define): `npm start`/`npm run dev` ya la quitan con `scripts/electron.js`; al lanzar `electron.exe` a mano en las pruebas hay que quitarla (`unset`).

## Arquitectura

- `electron/main.js`: ventana (arranca maximizada con `show: false` + `maximize()` en `ready-to-show`; F11 = pantalla completa por IPC y la interfaz recibe el estado con `window:fullscreen`), diálogos (incluida la pregunta al cerrar con cambios sin guardar: la interfaz avisa con `api.setDirty` y, si se elige Guardar, recibe `project:saveBeforeClose`), IPC (`ipcMain.handle`) y protocolo `media://` (sirve a la vista previa **solo** los archivos importados, con soporte de rangos y CORS, necesario para que WebGL lea los fotogramas).
- `electron/ffmpeg.js`: análisis (ffprobe), miniaturas, formas de onda (`peaks`) y renderizado a MP4 con `filter_complex`. Las rutas de ffmpeg/ffprobe se ajustan para `app.asar.unpacked` al empaquetar.
- `electron/preload.js`: única puerta entre interfaz y sistema (`window.api`). Cualquier función nueva del proceso principal se añade aquí y en `main.js`.
- `src/state/project.js`: modelo de datos y operaciones de edición como **funciones puras** que devuelven un proyecto nuevo (inmutable). El esquema está documentado al principio del archivo.
- `src/state/useHistory.js`: deshacer/rehacer. `set(updater, false)` actualiza sin crear paso (se usa durante los arrastres; al soltar se registra un solo paso).
- `src/App.jsx`: estado global, reproducción, atajos de teclado, abrir/guardar, portapapeles (interno, no el del sistema) y el contenido del menú contextual (`openContextMenu`; la línea de tiempo solo avisa de dónde se hizo clic derecho).
- `src/state/text.js`: medios de texto («Títulos y texto»). Un texto es un **medio sin archivo** (`kind: 'text'`, `text` con los parámetros, `isImage: true`) con un evento normal. `drawText` lo dibuja en un canvas de cuadro completo con fondo transparente: la vista previa usa ese canvas (en `Preview.jsx`, redibujado solo si cambia; el compositor lo vuelve a subir si cambia `cortexVersion`) y `renderPayload` manda el mismo dibujo como PNG (`png`), que `ffmpeg.render` guarda en un archivo temporal y usa como imagen. Medidas relativas a la altura del cuadro. Se guarda en el `.cortex` (`{ id, kind, name, text }`); al pegar, cada texto se copia como medio nuevo. En pausa se colocan con el ratón en la vista previa (`TextOverlay.jsx`, recuadro calculado con `textBounds`, las mismas medidas que `drawText`). Con efectos, los textos (y los PNG con alfa, `hasAlpha`) pasan `ctx.alpha` a `effectsGraph`: viñeta y croma conservan el alfa aparte.
- Vista previa a pantalla completa (`toggleFullScreen` en `Preview.jsx`, la llama `App` por `commands`): con una pantalla, `requestFullscreen()` del contenedor de la vista previa (sin los recuadros de texto/panorámica); con dos (`api.displayCount`), `window.open('', 'cortex-externa')`: `main.js` la deja abrir (`setWindowOpenHandler`) y en `did-create-window` la lleva a pantalla completa en la otra pantalla; muestra `canvas.captureStream()` en un `<video>` y reenvía las teclas a la ventana principal. Mientras está abierta, el lienzo se dibuja a la resolución del proyecto.
- Fuentes de los textos (`src/state/fonts.js`): 50 familias de Google Fonts en `public/fonts` (woff2, solo latín; licencias en `public/fonts/LICENCIAS.txt`), lista en `src/state/font-list.json`; las dos se generan con `node scripts/get-fonts.js .` (añadir familias en `FAMILIES`). `main.jsx` las registra y carga (`FontFace`) antes de dibujar la interfaz (unos 0,3 s): el lienzo de los textos usaría la fuente de reserva si no estuvieran cargadas, y el render usa ese dibujo. Las instaladas en el equipo salen de `window.queryLocalFonts()` (al abrir el selector, `FontPicker.jsx`).
- `src/state/pan.js`: panorámica/recorte del evento (`event.pan`, solo video): fotogramas clave `{ t, x, y, scale, rotation, smooth }` (t desde el principio del evento, x/y = centro de la imagen en fracciones del cuadro, scale respecto a la imagen encajada, grados en sentido horario) y `crop` fijo. Fórmula común: el punto q de la imagen (px del cuadro desde su centro) va a P + S·R·q. Vista previa: uniforms `uPan*`/`uCrop*` en `fit()` del compositor (fuera de la imagen, transparente). Render: `renderPayload` manda expresiones de FFmpeg con `@T@` (`panExpr`) y `ffmpeg.js` (`panChain`) centra la imagen en un lienzo `yuva444p` 2 px más grande (borde transparente) y usa `perspective` con `eval=frame` (**`in` vale 1 en el primer fotograma**; no pasar por RGB: cambia los colores de los videos BT.709). Los fotogramas clave se desplazan al recortar por la izquierda y dividir (`shiftPan`) y se escalan al cambiar la velocidad (`scalePanTime`). Edición: `PanDialog.jsx` (valores, tira de fotogramas clave) y `PanOverlay.jsx` (ratón en la vista previa).
- `src/state/envelopes.js`: envolventes de pista (`track.envelopes = { volume?: [{ t, v, c? }], pan?: [...], opacity?: [...] }`, v en dB, −1…1 o 0…1; volumen y panorámica en las de audio, opacidad en las de video: `envelopeKinds`) y panorámica fija `track.pan`. `c` = curva del tramo que sale del punto (`ENVELOPE_CURVES`: las de los fundidos + `hold`, escalón; sin `c`, lineal; volumen en amplitud); ley «balance» (`panGains`). Opacidad: `trackOpacityAt` en la vista previa (multiplica la de la capa, también en transiciones) y `trackOpacityExpr` en el render: `applyLevel` en `ffmpeg.js` hace una máscara gris con `geq` en un cuadro de 2×2 (calculada con el instante de cada fotograma) escalada, que multiplica el alfa (`alphaextract` + `blend=multiply` + `alphamerge`). **No usar `sendcmd` para valores que cambian en cada fotograma después de filtros con cola** (tpad, fps…): los comandos llegan antes que los fotogramas que esperan y el valor se adelanta (se probó con lutyuv: hasta 8 fotogramas).
- Modos de fusión de pista de video (`track.blend`, `BLEND_MODES` en `project.js`: multiply, screen, overlay, hardlight, darken, lighten, addition, subtract, difference). Vista previa: si alguna capa lo usa, el compositor compone en búferes intermedios (`acquire`) y mezcla con `BLEND_FRAGMENT` (fórmulas de `blend_modes.c` de FFmpeg, entradas [debajo][capa]); si no, dibuja directamente en el lienzo como siempre. Render: `compositeAt` pasa el trozo de debajo y la capa a RGB (`scale=in_color_matrix=bt601:in_range=tv`, ida y vuelta con la misma matriz), `blend=all_mode=…`, devuelve el alfa de la capa (`alphamerge`) y superpone. Con una transición de entrada en una pista con fusión, el evento se superpone desde que termina (no se mezcla dos veces).
- Transición en un fundido de video hacia la pista de debajo (`event.fadeInTransition` / `fadeOutTransition`, ids de xfade; `transIn`/`transOut` en los `fades` de `resolveTimeline`, `edgeAt` da el progreso): se pone soltando una transición sobre un evento sin solapamiento (`onDrop` de `Timeline.jsx`; crea un fundido de 1 s si no había). Vista previa: variante `edge` de los programas de transición (A y B = la misma imagen, un lado con alfa 0, mezcla RGBA; `vec3(` → `C4(`, negro/blanco opacos como en xfade). Render: `edgeTransitions` hace `xfade` entre el evento y una copia con `lutyuv=a=0` en yuva420p. Con transición, `fadeAt` no aplica ese fundido (lo hace la transición).
- Proxies de la vista previa: `probe` marca `needsProxy` (contenedor, códec de video o de audio que Chromium no reproduce: `BROWSER_*` en `ffmpeg.js`; HEVC se intenta y, si el reproductor da error, `Preview` avisa con `onMediaError`). `makeProxy` (H.264 ≤720 líneas, `-g 15`, AAC, mismos tiempos) y la cola en `main.js` (`proxy:make`, caché `userData/proxies/<sha1 de ruta|tamaño|fecha>.mp4`, archivo `.parcial.mp4` hasta terminar, progreso por `proxy:progress`; `media:analyze` devuelve `proxy` si ya existe). En `App`: `proxies` (original → proxy; no se guarda en el proyecto), `proxyJobs`, `noteAnalyzed` (todas las llamadas a `analyzeMedia` pasan por ahí), menú del medio y *Herramientas → Borrar los proxies*. `Preview` usa `sourceUrl(media)` para video y audio y rehace el reproductor si cambia la URL. El render usa siempre el original.
- En `buildRender` (`ffmpeg.js`), `n` es el índice de la entrada (`-i`): las etiquetas nuevas usan `tag`, no `n++`.
- Selección de tiempo y cursor se guardan en el `.cortex` como `view` (`serializeProject(project, view)`, `loadView`); no marcan el proyecto como modificado. Formato `.cortex` versión 9 (curvas de envolvente, opacidad, fusión, transiciones de fundido y `view`). Vista previa: `trackMixAt` en `Preview.jsx` (volumen en `setGain`, panorámica con un divisor de canales y dos ganancias en `AudioEngine.setPan`). Render: `trackMixExpr` da la ganancia de cada canal en función de `@T@` y `ffmpeg.js` añade a cada evento `aeval` antes de `adelay` con T = t + inicio del evento (muestra a muestra). Dibujo y edición en `Timeline.jsx` (`EnvelopeLines`, `onEnvPointDown`…); escala de volumen de raíz cuadrada (0 dB a un 70 % de la altura, +6 dB arriba).
- Render: `src/state/render-formats.js` (formatos, tamaños, plantillas y `outputSize`, que calcula el tamaño del archivo y el del proyecto dentro de él) y `OUTPUT_FORMATS` en `electron/ffmpeg.js` (argumentos de cada codificador; mismos ids). `settings` del render: `{ width, height` (montaje) `, outWidth, outHeight` (archivo: si difiere, `pad` con bandas negras) `, fps, format, quality: { mode: 'crf', level } | { mode: 'bitrate', mbps }, audioKbps }`. Solo audio (MP3/WAV): no se monta el video; GIF: `palettegen`/`paletteuse` y el audio va a `anullsink`.
- Grabación de voz en off (`src/preview/recorder.js`): `Recorder.prepare` abre el micrófono (sin cancelación de eco ni reducción de ruido salvo en las opciones, `localStorage` `cortex-record`) y pide a `main.js` el archivo (`record:start`, WAV mono de 16 bits en `Grabaciones` junto al proyecto o en Documentos); un AudioWorklet manda las muestras a trozos (`record:write`, la cabecera se actualiza cada 5 s por si se cierra de golpe) y `record:stop` cierra el archivo. En `App`, `startRecording` arranca la reproducción y el efecto del reloj llama a `begin()` justo cuando empieza a contar (así la muestra 0 = el instante de partida); grabando, el reloj no se para al final del proyecto ni hace bucle, y parar la reproducción por cualquier vía llama a `finishRecording`, que importa el WAV y coloca el evento con `inPoint` = retardo estimado (`baseLatency + outputLatency` + latencia del micrófono). Pista armada (`armedTrackId`) y grabación en curso no se guardan. Pruebas: Electron con `use-fake-device-for-media-stream`, `use-fake-ui-for-media-stream` y `use-file-for-fake-audio-capture=<wav>` (un WAV de pitidos para comprobar dónde caen).
- Medidores de volumen (`src/preview/meters.js` + `Meter.jsx`): en `AudioEngine`, cada reproductor va al bus de su pista (`bus(trackId)`) y los buses al máster; cada bus tiene un `AnalyserNode` por canal y `levels()` da los picos. `meters.js` los lee en su propio `requestAnimationFrame` y escribe en el DOM solo si cambia algo (sin React). Comprobado: un tono de −6 dBFS marca −6,0 dB.
- Actualizaciones automáticas (`electron-updater`, en `main.js`: `setupUpdates`): solo con la app instalada (`app.isPackaged`); `publish` de `package.json` apunta a las releases de GitHub (electron-builder mete `app-update.yml` en el instalador). Busca a los 4 s de arrancar, descarga sola y manda el estado a la interfaz (`update:state`: checking, downloading con `percent`, ready, latest, error); `App.jsx` enseña el aviso (`update-banner`) y *Ayuda → Buscar actualizaciones…*. «Reiniciar y actualizar» cierra la ventana (con la pregunta de guardar de siempre) y en `window-all-closed` llama a `quitAndInstall(true, true)`; «Al cerrar» = `autoInstallOnAppQuit`. Sin firma, electron-updater no comprueba el editor (solo el sha512 de `latest.yml`). Para probar sin publicar: `CORTEX_UPDATE_URL=<servidor>` usa un proveedor genérico; se probó instalando una compilación con otro `appId`/`productName` (`-c.appId=… -c.productName="Cortex Prueba" -c.extraMetadata.version=…`) en una carpeta temporal (`Setup.exe /S /D=…`) y sirviendo la versión siguiente con un servidor local.
- Guardado automático: cada minuto (`AUTOSAVE_MS` en `App.jsx`), si hay cambios, `api.autosave` escribe `userData/autosave/recuperacion.json` (`{ savedAt, projectPath, data }`); se borra al guardar y al cerrar la ventana normalmente (`closed` en `main.js`). Si existe al arrancar, se ofrece recuperarla (`loadData(data, path, true)`: queda como modificado). Guardar encima de un archivo deja la versión anterior en `.bak`.
- Marcadores y regiones (`project.markers` `{ id, time, name, number }` y `project.regions` `{ id, start, end, name, number }`, formato `.cortex` versión 7): franja `MarkStrip` en la regla (`Timeline.jsx`), M / R / 1–9 en `App`. Entran en el ajuste y en Ctrl+←/→ (`markPoints`), la cascada en todas las pistas los mueve (`shiftMarks`) y `RenderDialog` puede renderizar una región.
- Edición en cascada (`ripple` en `App`: null, `'tracks'` o `'all'`; Ctrl+L; no se guarda): `rippleDelete` (cierra los huecos sin contar el tiempo que siguen ocupando otros eventos de la pista, p. ej. transiciones), `rippleShift` (pegar inserta) y `deleteRange` (Ctrl+Supr: quita el tramo de la selección de tiempo de todas las pistas), en `project.js`. Al mover o recortar el final en `Timeline.jsx`, los eventos de detrás (`followers`) se desplazan lo mismo.
- Selección de tiempo (`region` en `App`, no se guarda ni se deshace): barra de arriba de la regla en `Timeline.jsx` (`onRegionDown`), doble clic en un evento, Esc. La reproducción que empieza dentro se para al final o hace bucle (Q). `renderPayload(project, size, range)` quita los eventos de fuera y `buildRender` monta todo en tiempos de la línea de tiempo con la base empezando en el fotograma del principio (`setpts=PTS+first`) y al final quita lo anterior (`setpts=PTS-STARTPTS`, `atrim`): sale idéntico a ese trozo del render completo.
- `src/state/transitions.js`: catálogo de transiciones agrupado como en VEGAS. Cada preajuste es un `transition=` de `xfade` de FFmpeg.
- `src/state/effects.js`: catálogo de efectos de video (FX de evento). Cada efecto define sus parámetros y su filtro de FFmpeg (`ffmpeg(p, ctx)` lineal o `graph(...)` con ramas, p. ej. el brillo difuso). Las medidas son **relativas a la altura de la imagen** para que vista previa y render coincidan. `effectsGraph` monta la cadena con etiquetas `@IN@`/`@OUT@`/`@N@` que rellena `electron/ffmpeg.js`. Si un efecto deja transparencia (croma), los siguientes deben conservar el alfa (`gbrap`, no `gbrp`).
- Fotogramas clave de los efectos de video (`fx.keyframes = [{ t, params }]`, t local del evento; en `effects.js`: `fxParamsAt` interpola los `range` y el resto cambia al llegar; `setFxValues`, `addFxKey`, `removeFxKey`, `moveFxKey`, `shiftFxKeys`/`scaleFxKeys` al recortar, dividir y estirar con Ctrl). Vista previa: `activeEffects(effects, tLocal)`. Render: `effectsGraph(…, timing)` genera el grafo con `ctx.keep` (filtros siempre presentes), pone nombre a cada filtro (`filtro@@N@a0k1`) y saca de cada fotograma los comandos de las opciones que cambian (`cmds`, medio fotograma antes); `ffmpeg.js` (`fxCommands`) los convierte en un `sendcmd` antes del subgrafo, con los valores acumulados al principio de cada trozo. Solo efectos cuyos filtros admiten comandos (`animatable: false` en Enfocar/unsharp, Viñeta/vignette y el umbral del brillo difuso, que va en una expresión de lutrgb con comas). Comprobado: cada fotograma animado = render fijo con esos valores (diferencia 0).
- `src/state/audio-effects.js`: catálogo de efectos de audio (mismo formato; `effects.js` los une en `EFFECTS` con `kind: 'video' | 'audio'`). Cada evento de audio lleva `afx` en el payload del render (subgrafo con `@IN@`/`@OUT@`), aplicado antes de los fundidos y cortado a la duración del evento.
- `src/preview/audio-engine.js` y `audio-fx.js`: audio de la vista previa con Web Audio. Cada reproductor (`<audio>` con `crossOrigin`, si no Web Audio recibe silencio) → cadena de efectos (`AudioChain`, solo se rehace si cambia la lista) → ganancia (pista × evento × fundidos, puede pasar de 1). Puerta de ruido, compresor (el `DynamicsCompressorNode` añade ganancia automática) y cambio de tono son AudioWorklets propios que copian los filtros de FFmpeg.
- Pruebas automáticas: `window.cortexPruebas` (en `Preview.jsx`) expone `renderOfflineAudio` y el motor de audio para comparar vista previa y render.
- `src/preview/effects-gl.js`: los mismos efectos como pasadas de shader (mismas fórmulas que el filtro de FFmpeg; eq/hue/vignette trabajan en YUV BT.601 de rango limitado). Para añadir un efecto: entrada en `effects.js` + pasadas en `effects-gl.js`, y comprobar que vista previa y render coinciden.
- `src/preview/compositor.js`: compositor WebGL2 de la vista previa. Las transiciones son traducciones a GLSL de `vf_xfade.c` (P va de 1 = solo A a 0 = solo B; `mixx(a,b,m) = a·m + b·(1−m)`), para que la vista previa coincida con el render. Para añadir una transición: entrada en `transitions.js` + fragmento en `GLSL` del compositor. Hay un programa para las capas normales y uno por transición, compilado la primera vez que se usa (`programFor`): **no volver a meter todas las transiciones en un mismo shader** ni añadir ramas en `fit()`, que se copia en cada una; Direct3D tardaba hasta 30 s en compilarlo sin caché y la ventana no se pintaba (parecía que la app no arrancaba). Para comprobarlo, arrancar con una carpeta de datos nueva (`app.setPath('userData', …)`): las pruebas con caché no lo detectan. Los efectos se aplican antes de componer, a la imagen encajada (sin bandas), en búferes intermedios (`applyEffects`).
- `src/components/`: MenuBar, Toolbar, Dock (con pestañas), MediaPool, TransitionsPanel, Preview (un `<video>` oculto por evento cercano al cursor; el compositor toma sus fotogramas), Timeline, Transport, Waveform y diálogos (Project, Render, Shortcuts).
- `src/styles.css`: un único archivo de estilos, tema oscuro estilo editor clásico.

## Convenciones del modelo

- Tiempos en **segundos** (float). `MIN_EVENT` = duración mínima de un evento.
- Pistas ordenadas de arriba a abajo (la de video de más arriba se dibuja encima). Como en VEGAS, una pista de video nueva va arriba del todo y una de audio abajo del todo (`addTrack`; pegar usa `'afterType'`), y se pueden reordenar arrastrando su cabecera (`moveTrack`), también mezclando video y audio.
- Un video con sonido = dos eventos con el mismo `groupId`; se mueven, recortan y dividen juntos.
- Volumen de pista en dB (`MIN_VOLUME_DB` = silencio, máximo `MAX_TRACK_VOLUME_DB` = +12 dB; el de evento, máximo 0 dB). Silencio/solo se resuelven con `isTrackActive`.
- Velocidad: cada evento tiene `rate` (1 = normal, de `MIN_RATE` 0,25 a `MAX_RATE` 4; Ctrl + arrastrar un borde). `duration` es lo que ocupa en la línea de tiempo y del medio se usan `duration × rate` s desde `inPoint`: para pasar a tiempo del medio usar siempre `sourceTime(e, t)` (dividir, recortar, `playerKeys`, sincronizar reproductores con `playbackRate`, forma de onda, `eventPeak`). En el render: `setpts=(PTS-STARTPTS)/rate` antes de `fps` y `atempo` (encadenado por debajo de 0,5) en el audio, que conserva el tono como el navegador.
- Rampas de velocidad (`src/state/speed.js`): `event.speed = [{ t, v }]` (t local, v factor de 0,1 a 4, lineal entre puntos, constante fuera) que multiplica a `rate`; del medio se usa la integral (`sourceOffset`, inversa `localForSource`), y `sourceTime` ya la usa. Se aplica al grupo (`setSpeed` en `Timeline.jsx`), se desplaza al recortar por la izquierda y dividir (`shiftSpeed`) y se estira con Ctrl (`scaleSpeedTime`). Vista previa: `playbackRate` = `speedAt` en cada fotograma (los eventos con rampa no comparten reproductor). Render: `renderPayload` manda los tramos (`speedPayload`); el video usa `setpts` con la inversa exacta (`localExpr` en `ffmpeg.js`) y el audio `rubberband` con comandos de `asendcmd` cada 20 ms (**no atempo**: pierde ~3 ms en cada cambio y la rampa se adelanta) más 0,5 s de medio de sobra y `atrim`. Comprobado con un video que lleva su número de fotograma en el brillo: vista previa = render = fórmula; sonido a menos de 20 ms.
- Cada evento tiene `volume` (dB, solo afecta al audio), `fadeIn`, `fadeOut` (segundos), `fadeInCurve`/`fadeOutCurve` (`FADE_CURVES`: linear, fast, slow, smooth, sharp; formato `.cortex` versión 8) y `transition` (id de la transición de entrada; `null` = disolución cruzada). En video el fundido es de transparencia (`fade ... alpha=1` en FFmpeg si es lineal; con curva, `geq` multiplica el alfa solo en los fotogramas del fundido; opacidad de capas en el compositor). Factor del fundido: `fadeAt`/`fadeFactor` en `project.js` (entrada = `fadeCurve(curva, p)`, salida = 1 − `fadeCurve(curva, p)`); en audio, `afade` con `curve=` (ipar, qua, hsin, ihsin: en la salida rápido y lento se intercambian, ver `AFADE_OUT`). Comprobado: render y fórmula difieren menos de 0,01.
- Solapamientos: si un evento empieza dentro de otro de su pista y termina después, es una transición. `resolveTimeline(project)` calcula los solapamientos (`incoming`/`outgoing`), las transiciones de video y los **fundidos efectivos** (`fades`): en audio el solapamiento es un fundido cruzado; en video la transición anula los fundidos de esos bordes. Usar siempre esos fundidos (render, vista previa y línea de tiempo), no los guardados.
- Render de una transición: entradas aparte con el final de A y el principio de B, `xfade` entre ellas y `overlay` encima del evento B, dentro del orden de su pista.
- Render de video sobre la **rejilla de fotogramas**: cada fragmento ocupa los fotogramas cuyo instante cae en [inicio, fin) (`frameSpan`), se desplaza por fotogramas enteros y se superpone solo en ellos. No volver a desplazar por segundos: el redondeo dejaba un fotograma negro en los cortes.
- Vista previa sin pausas en los cortes: eventos seguidos que continúan el mismo archivo comparten reproductor (`playerKeys` en `Preview.jsx`), y los reproductores de video y audio de los eventos que empiezan en los próximos 2 s se cargan por adelantado.
- **Rendimiento**: durante la reproducción, `App` y casi todos los componentes se vuelven a dibujar en cada fotograma (cambia `time`). Nada caro (WebGL, audio offline, recalcular curvas, `postMessage` a worklets) puede ejecutarse en cada dibujado: usar dependencias estables en los `useEffect` (ids, no objetos creados en cada render) o cachés, y comprobar si los valores cambiaron de verdad (como `AudioChain.set` y `AudioEngine.setGain`). Las miniaturas de `EffectsPanel` se calculan una vez por sesión. En los shaders, los bucles deben recorrer solo las muestras que se usan (límite calculado), no un máximo fijo con `continue`.
- Archivo `.cortex` = JSON de `serializeProject` (`format: 'cortex-studio'`, `version`). Miniaturas y formas de onda no se guardan; se regeneran al abrir. Si cambia el formato, `loadProject` debe seguir abriendo los archivos antiguos (rellenar campos por defecto).
- IDs con `uid(prefijo)`: `t` pistas, `e` eventos, `g` grupos.

## Para empezar en otro equipo

```bash
git clone https://github.com/Nyra31/cortex-studio.git
cd cortex-studio
npm install      # descarga Electron, FFmpeg y ffprobe
npm start
```

Si `npm start` dice que `vite` no se reconoce, falta `npm install`. Si falta `node_modules/electron/dist/electron.exe` (con npm 11 la descarga de Electron puede no ejecutarse), lanzar `node node_modules/electron/install.js`.

`dist/` y `release/` no están en el repo: se regeneran con `npm run build` / `npm run dist` (el instalador solo se puede generar en Windows).
